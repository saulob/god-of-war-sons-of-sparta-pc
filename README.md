# God of War: Sons of Sparta — PC Port

Native Windows port of the PlayStation 4 release of *God of War: Sons of Sparta*
(`CUSA57767`, USA), in the same style as Saulo's other PS4 ports: the game's own
x86-64 code runs directly on the PC, with replacement PS4 system libraries and a
Vulkan renderer derived from shadPS4. **The game is not included** — bring your own
legally obtained PS4 package.

## Status

The supported game build is identified, the boot image and import database are generated by
the preparation pipeline, and the game's own x86-64 code runs through the native
loader/runtime and the shadPS4-derived video core. The launcher installs/selects the game and
PLAY starts it. Runtime validation is performed manually.

- Engine: **Unity 2022.3.62f3, IL2CPP**, URP (2D), FMOD, Addressables, Burst.
- Architecture: native relink of the PS4 SELF/ELF modules + shadPS4-derived
  `libSceGnmDriver`/`libSceVideoOut` Vulkan video core.

## Features

- True Ultrawide Hor+ at 21:9 and 32:9, with configurable render resolutions
- Configurable frame rate (30, 60, 90, 120, 144, 165, 240 FPS, or Unlimited)
- SMAA anti-aliasing
- Skip Intro
- Exit Game in the title menu
- Xbox controller prompts
- Hermes Mode early unlock (off by default)

## Display & True Ultrawide

The launcher supports configurable render resolutions, aspect ratios (including 21:9 and 32:9 True Ultrawide Hor+), and frame rate options. True Ultrawide expands the horizontal field of view while preserving the vertical view and HUD proportions; because the original game was authored for 16:9, some 2D scenes may show visual edges of the original backgrounds.

## Hermes Mode

Hermes Mode is the game's original speedrun mode. The PC port provides an **Unlock Hermes Mode** option in the launcher's **Gameplay** tab, disabled by default.

While enabled, Hermes Mode is available from the beginning: the original GAME MODES screen offers Campaign, Erebus Mode and Hermes Mode when creating a new game, without completing the campaign or entering the secret code. Campaign and Erebus Mode remain available. Turning the option off restores the game's original availability requirement; the original cheat-code unlock still works, and an existing Hermes save still loads normally.

Hermes Mode is selected in the original GAME MODES screen, not in the launcher. As in the original game, the selected game mode is stored with the save and cannot be changed afterward. Existing saves are not modified, and the selection is saved through the game's normal save system.

## Build and run

From the repository root:

```powershell
.\tools\build.ps1                # configure and build; refresh an installed game's boot image
.\tools\build.ps1 -Run           # same, then opens the launcher (numbered session log)
.\tools\build.ps1 -Run -CheckImports   # same, with the complete unresolved-import inventory
```

The game is installed from the launcher (Play page, `Install game...`), as in a release.
`tools\build.ps1` fetches the pinned video core dependencies and LibAtrac9 (MIT, the ATRAC9 decoder of libSceAjm), builds the pinned LGPL FFmpeg of the video player
into `cache\deps` (a few extra minutes the first time), configures and builds with CMake + Ninja,
and rebuilds the boot image of an already installed game when it is stale. It never selects or extracts
packages: `game\prepared` and `build\image` are written by the launcher.

`-Run` starts `sons_of_sparta.exe`: the launcher opens first, PLAY starts the game, and the loader maps the boot image, initializes the runtime and the
shadPS4-derived video core, and calls the guest entry point. A `-Run` writes one session log
`build/logs/sons_of_sparta_NNN.log` holding the `[build]` section and then the `[run]` section;
a build without `-Run` writes `build/logs/build/build_NNN.log`. The session counter is kept in
`build/.sons_of_sparta_log_sequence`, so deleting the logs does not reuse a number.

`-Run -CheckImports` runs the headless import diagnostic instead of the game and prints the
complete unresolved-import inventory.

`-Clean` rebuilds `build/cmake` from scratch; `tools\setup.ps1` checks prerequisites;
`tools\clean.ps1` removes only the CMake tree.
`tools\clear-startup-cache.ps1 [-Status]` reports or deletes only the startup red-zone cache (`user\cache\CUSA57767\redzone`).

## Module graph (what the loader links natively)

`eboot.bin` → `sce_module/libc.prx` → `sce_module/libSceFios2.prx` →
`Media/Modules/PS4Util.prx` → `Media/Modules/Il2cppUserAssemblies.prx` (135 MB of
compiled IL2CPP C#). Everything else (libkernel, libSceGnmDriver, FMOD, …) is provided
by the host runtime.

## Milestone plan

1. Reliably identify the supported game build (done: `scripts/game_profiles.py`).
2. Process/load the executable modules (done: boot image + loader + import database).
3. Resolve initial imports and implement the filesystem/remaining first-layer libraries.
4. Reach the executable entry/init, then Unity initialization and a first frame.
5. Title screen, input, audio, gameplay.
